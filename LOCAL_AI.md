# Local AI routing & data-egress policy

## What is actually local

Every completion the **application** produces is generated by Ollama on
this machine, over `http://localhost:11434`. No prompt, message, file, or
piece of chat history is sent to a hosted AI provider. This is verified,
not assumed - see the audit table below.

Configure the endpoint and models in `.env`:

```bash
OLLAMA_URL=http://localhost:11434
```

Models the app selects between (see `preferredModel()` in
`static/script.js`):

| Bay   | Model               | Why |
|-------|---------------------|-----|
| Code  | `qwen2.5-coder:7b`  | code-tuned, materially better at code than a general model |
| Chat  | `llama3.2`          | smallest general model - chosen for speed, see note below |
| Image | `stabilityai/sd-turbo` | local diffusion, CPU, via `imagegen.py` |

`qwen2.5:7b-instruct` is also pulled and is more accurate than
`llama3.2`, but it is *not* the chat default on purpose: this machine
has ~8GB of VRAM and can hold one multi-GB model at a time, so switching
models costs a ~39s cold load against ~1.4s warm. Pick it manually from
the model dropdown when accuracy matters more than latency.

## Complete outbound-network audit

Every outbound call in the codebase, and what triggers it:

| Location | Destination | When | Leaves machine? |
|---|---|---|---|
| `app.py` `stream_ollama()` | `localhost:11434` | every chat message | **No** - loopback |
| `app.py` `ollama_provider()` | `localhost:11434` | model list refresh | **No** - loopback |
| `websearch.py` | duckduckgo.com | only when web search runs | Yes - the search query only |
| `app.py` Google OAuth | accounts.google.com | only on sign-in click | Yes - only if `GOOGLE_CLIENT_ID` set |
| `imagegen.py` Gemini | generativelanguage.googleapis.com | only if `GEMINI_API_KEY` set **and** Gemini selected | Yes - the image prompt only |

There is **no telemetry, analytics, or crash reporting** anywhere in the
codebase. The three egress paths above are each opt-in or explicitly
user-initiated, and none of them carry chat history.

To guarantee zero egress, leave `GOOGLE_CLIENT_ID` and `GEMINI_API_KEY`
unset and don't use Deep mode (which forces a web search). The app is
fully functional in that configuration.

## Claude Code itself cannot route through Ollama

Worth stating plainly, because it is a common and reasonable
expectation:

**Claude Code runs on Anthropic's API. There is no configuration that
makes its own completions come from a local model.** That is
architectural, not a setting.

The obstacle is protocol, not policy: Ollama serves an *OpenAI*-shaped
API, while Claude Code speaks Anthropic's. Even `ANTHROPIC_BASE_URL`
won't bridge that without a translating proxy (LiteLLM and similar can
do it) - and that path is unsupported, breaks on API changes, and gives
up the model quality that makes an agent useful.

If the goal is a coding agent whose inference stays on this machine, use
a tool built for it:

- **Continue.dev** - VS Code extension, first-class Ollama support
- **Aider** - terminal-based, `aider --model ollama/qwen2.5-coder`
- **Cline** - VS Code agent, supports local endpoints

All three will happily use the `qwen2.5-coder:7b` model already pulled
here. What Claude Code *does* respect is the read/write restrictions in
`.claude/settings.json`, which stop it opening `.env`, the database, or
credentials in the first place - see `.claudeignore` for the manifest.
